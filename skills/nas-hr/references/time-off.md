# Time Off / Vacation Module (reference) — Designing

A **standalone** sidebar module replacing old "vacation" thinking with a dynamic, configurable Time Off engine — HR can create ANY leave type for ANYONE without code changes.

> **Single source of truth:** `/Users/krim/Desktop/time-off-business-handoff.md` — read it first; it has the full field-by-field detail. This file is the resumable summary. See also memory `project_hr_timeoff_module.md`.

## Structure
**Pages (5):** Types · Requests · Balances · Official Holidays · Settings (no Overview).

**Type config = SINGLE PAGE with TABS under the header (canonical, decided 2026-06-18 — SUPERSEDES the earlier 2-step/wizard note).** Rationale: a single long page was a confusing wall of fields; the 2-step felt heavy. Final = one route, sections become tabs. Built at full DS fidelity (real Sidebar/Header/Input-Field component instances).
- **Header:** `Create Time Off Type` + persistent Cancel/Save (Discard/Save in the live build) across all tabs. Tabs: **Basics · Balance · Requests · Eligibility** (active = dark text + dark bottom underline).
- **Basics tab** ("Type Basic Information"): Type Name EN/AR · Stock Source · **Payment Type** (was "Pay Treatment" — renamed) · Approval Workflow · Notes. Stock Source is the master switch (drives the Balance tab).
- **Balance tab** ("Balance Rules"): **Balance Method** (was "Yearly Balance Method"; Fixed / Tiered) → when Tiered, **Entitlement Tiers** builder. Each tier row is structured: **Unit ▾ (Years of Service / Age) · Operator ▾ (≥) · Number → Entitlement (days) · ✕** (unified unit per row, replaces old free-text "0+ service years" mix). Subtitle = plain rule "If an employee matches more than one row, the highest entitlement applies." Then **Carry over** checkbox + Max Carry Over Days · Carry Over Expiry · Expiry After (months). NOTE: "Balance Granting"/accrual DROPPED; Cycle/Rounding/New-joiner moved to Settings only (see below).
- **Requests tab** ("Request Rules"): Eligibility Period (number + unit "Months", labeled "After Joining") · **Notice Days Before Leave** (number + "Days"; was "Advance Notice Required") · Count Days By (Working Days Only / Calendar / Calendar-excl-holidays) · **Attachment Required** checkbox → "What to upload" instruction field + "multiple files" helper. **Both "Maximum Days Per Request" AND "Maximum Requests" use the same conditional control: a mode dropdown (No Limit/Limited or Unlimited/Limited) + a Number field that is HIDDEN when "No Limit/Unlimited" and appears when "Limited."** Limit Period field DROPPED — the Maximum Requests number is always a LIFETIME total (backend blocks once reached; HR can edit anytime); no Per-Year/Per-Service choice. Real lifetime cases: Maternity 3×, Hajj 1×. A dedicated doc frame "TABS 3b · Requests (Max Days = Limited example)" shows the expanded state for developers.
- **Eligibility tab** ("Eligibility Rules") — BUILT 2026-06-18: **Applies To** (full-width dropdown, options **All employees / Male / Female** — absorbs gender; the separate Gender field was REMOVED) + helper "'All employees' = everyone. Choose Male or Female to limit by gender — e.g. Maternity → Female only." · **Religion** (options **All / Muslim / Christian**). Org-restriction by Department/Branch/Job Grade/Employment Type was **DROPPED** (not needed). All four tabs (Basics · Balance · Requests · Eligibility) now built at DS fidelity.
- Numeric fields (Notice, Max Days, etc.) = number inputs ("Unlimited/No limit" = blank); Count Days By / Limit Period / Stock Source / Payment Type / Balance Method = dropdowns.
- **DROPPED 2026-06-18: "Balance Granting" field (Manual / Full-at-year-start / Earn Monthly) removed entirely.** Accrual ("Earn Monthly") added nothing the business needs — current live system grants balance manually per employee, and new-joiner fairness is already handled by the Settings "New Joiner: Prorated" rule. Entitlement number comes from the tier table; release pace is not a per-type config.
- (Old 2-step "Step 1 minimal create → Step 2 rules tabs" flow is fully SUPERSEDED by the single-page-tabs above.)
- **Global defaults (Cycle Basis · Rounding · New Joiner) live ONLY on the Settings page** — they are company-wide accounting conventions, NOT per-type. DECISION 2026-06-18: removed from the type form entirely (the old "from company Settings · Override" context note on the Balance tab is gone). No per-type override (YAGNI; same call as Balance Granting). If an override need ever emerges, add it then.
Active/Inactive from list actions only; historical data frozen on edit/inactivate; delete only if unused. Backend owns all balance math (generation, tiers, recognized-service, proration, rounding, carry-over + expiry, pending reservation, used-deduction-on-approval, validation).
**Types List page** (BUILT 2026-06-18, frame "Requests List - Offsite Work Types" — misnomer, displays "Time Off Types"): columns = ☑ · **Type Name** · **Entitlement** (e.g. "21–30 (tiered)", "90 days", "—" when it draws from another type) · **Payment** · **Stock Source** (Own Balance / From Annual / No Balance) · **Applies To** (All / Female …) · **Approval Cycle** (named workflow, e.g. "Annual Approval") · **Status** (Active badge) · **Actions** (⋯). Toolbar: Filter · Export · Import · Search · settings gear · "New Time Off Type" button. Pagination footer. FINAL content (settings-list layout — each row = title + subtitle on the left, control on the right, dividers between): **Leave Year Resets** (merged Cycle Basis + Leave Year Start: a mode dropdown "On a fixed date" / "On joining anniversary" + a date dropdown e.g. "1 January" that shows ONLY for the fixed-date option) · **Rounding** (Round down / decimals / up) · **Default Approval Workflow** (fallback when a type has no workflow). ## Gap-audit RESOLVED 2026-06-17 (critical gaps — all locked, supersede older doc text)
1. **Pay model** — `Pay Treatment` = Fully Paid / Unpaid / **Partially Paid** + `Pay Schedule` (cumulative days→pay %, e.g. sick 1-90=75%, 91-180=85%). Replaces Paid/Unpaid binary.
2/3. **Caps** — `Max Days/Request` + **`Max Days/Year`** (NEW) + `Max Requests` with **Per-Year / Per-Service (lifetime)** scope (NEW) → unlocks sick annual cap + maternity 3×/hajj 1× lifetime.
4. **Eligibility** — `Eligibility Period` = min service MONTHS from joining date; NEW generic **`Applies To`** scope (Dept/Branch/Grade/Employment-Type, include/exclude) + Gender + Religion.
5/6. **Tier Builder** — rows `(Service Years | Age) ≥ threshold → days`; **grant the MAX** of matching rows (Egyptian annual: Service≥0→21, Service≥10→30, Age≥50→30). Two service concepts: **Company Service** (eligibility) vs **Recognized Service** = company + **Recognized Previous Experience** (employee-profile field, manual + import) (tiers). Per-type **Tier Basis toggle** (Recognized [default] / Company-only).
7. **Cancellation** — Pending→employee self-cancels; Approved→**HR-only**; mid-leave HR cancel refunds **unused future days** only; Completed→locked (audited adjustment).
8. **Overlap** — backend blocks vs Pending/Approved leave + cross-checks Errands/إذن same day.
9. **Status** — **driven by the type's Approval Cycle** (Approval Workflow Engine): the *pending* state reflects the **current workflow step** (e.g. "Pending — Direct Manager", "Pending — HR"; a 1-step workflow = just "Pending"); step names come from the workflow, NOT a fixed list. Universal: **Approved** (all steps passed) · **Rejected** · **Cancelled**; time-driven: **On Leave** (dates active) · **Completed** (dates passed). Clarified 2026-06-18 (reflected in NEW2B-4193).
10. **Cross-cycle** — requests spanning two cycles are **BLOCKED** (submit two requests).
11. **Integration** — **Time Off → Attendance ONLY** (sets day-type paid-excused/unpaid); **NO direct payroll link** — payroll-v3 derives deductions from attendance as it already does. Pay-% schedule is informational/coverage (Egypt partial sick pay = social insurance, not company payroll).
★ **Approval = PER-TYPE** (OVERRIDES doc's old module-level rule): Type carries an **`Approval Workflow`** field selecting a workflow from the Approval Workflow Engine; no-workflow → HR-step fallback. Manager/HR checkboxes stay removed. (See `errands-partial-day.md` and memory `project_hr_approval_workflow.md`.)

## Medium gaps RESOLVED (round 2, 2026-06-17)
- **Backend-standard conventions:** proration = days from join→cycle-end then rounding; accrual = yearly/12 per month, can't spend unaccrued; rollover = backend at cycle boundary; "Working Days Only" = backend reads existing shift/work-calendar module.
- **Backdated requests** — NO per-type field. Allowed for past dates **until the payroll period covering those dates is closed** (manager approves). Reason: unfiled absence gets deducted. Global behavior tied to payroll-v3 pay-period open/closed status; locked once period closes.
- **Settings vs Type** — Settings page holds company-wide rules (Cycle Basis, Rounding, New-Joiner, Allow-HR-submit, Import validation); type keeps type-specific rules; each global rule on the type form defaults to "Use company default" with optional Override (clean + flexible). Always-on behaviors (pending-reserve, block-negative, audit) aren't toggles.
- **Deduct From Another Type** — adds a `Source Type` picker; Sick (no own bucket) draws from Annual 21-day balance; usage shows under Annual's row (tagged "via Sick").
- **Opening-balance import** — columns: Employee Code · Name (optional) · Time Off Type · Cycle Year · Total Entitlement · Carry-Over In (optional) · Used · Note. Used = plain number (not historical requests); Pending NOT imported; Remaining computed = Total + Carry-Over In − Used; Recognized Previous Experience rides on the employee-profile import.
- **Mid-cycle tier change** — new tier applies at **next cycle generation**, not mid-cycle.
